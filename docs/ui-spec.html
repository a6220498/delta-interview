  • 編輯是真的表單，不是可寫的段落標題不再是 contenteditable。contenteditable 在讀屏軟體上的行為各家不一，而且它把「一段文字」偽裝成輸入框；改成選單的「編輯」開啟同一張彈窗後，鍵盤使用者拿到的是有 <label>、有錯誤訊息、Esc 可退出的正規表單。必填的語意由 required 承擔，紅星只是給用看的人的記號，所以星號 aria-hidden —— 讀屏會唸「必填」，不必再聽到一個孤零零的「星號」。訊息列用 aria-live="polite" 並以 aria-describedby 綁回欄位，錯誤出現時唸得到，也不會打斷正在輸入的人。
  • 選單用原生 popover點外面自動關、Esc 可關、關閉後焦點回到三點鈕，而且面板開在 top layer，不會被托盤裁掉或被下一張單子蓋住。三點鈕視覺 26px、靠 ::before 把命中區撐到 44×44，且常駐不靠 hover —— 觸控裝置沒有 hover。
  • 狀態不只用顏色紫色配全填方框、刪除線與「完成」章，紅色配「逾期」文字標籤（WCAG 1.4.1）。把顏色全部拿掉，靠方框與蓋章的形狀仍然分得出來。類別也走同一條線：存根頂端的記號用實心（bug）對空心（feat）的形狀差異，不另開一組類別色 —— 卡片上的顏色已經被逾期與完成用掉，第三條色軸會跟它們搶注意力。記號對讀屏是冗餘的（底下的單號本來就印著 bug／feat），所以整塊 aria-hidden。
  • 彈窗用原生 <dialog>焦點鎖在彈窗內、Esc 可關、關閉後焦點自動回到剛才那顆按鈕 —— 這些瀏覽器已經做好，不必自己接。手機浮動鈕 56×56、距邊 16px，且不壓到最後一張單子。
  • 整張卡片可點，但無障礙樹只多一顆按鈕標題本身是 <button>，用 ::after 把感應區撐滿整張卡（stretched link）。整張 .docket 掛 click 會做出巢狀互動元素，方框與三點鈕還得靠 stopPropagation 補救；改成這樣，那兩顆是按鈕的兄弟節點，不必攔任何事件。aria-label 把單號墊在前面，可見的標題整段包含在內（WCAG 2.5.3）。焦點框畫在覆蓋層上，框住的是真正可按的範圍。拖曳與點擊不必自己分辨 —— 原生 DnD 完成一次拖曳後就不會再派 click。代價寫在這裡：覆蓋層蓋住整張卡，卡片上的文字選不起來。
  • 明細是拿來讀的，所以焦點落在窗本身明細窗宣告成一般 <dialog>（不是 alertdialog —— 沒有危險也沒有決定要下），開啟時把焦點放在窗上（tabindex="-1"）而不是「關閉」；WAI-ARIA APG 對「內容為主」的彈窗就是這樣建議，焦點丟到「關閉」等於一開場先把人帶到出口。說明還沒到時，那一塊掛 aria-busy，aria-live 只給下面那一行狀態字 —— 掛在內文上的話，說明一到就會把整段唸出來，而那可能是 2000 字。狀態列常駐在 DOM 裡只換字（整塊連元素一起塞進去的 live region，很多讀屏軟體不會唸）；失敗那塊則相反，用 role="alert"，插進來就會唸。
  • 破壞性動作不能是預設焦點刪除確認宣告成 role="alertdialog" 並用 aria-describedby 指向警告句，開啟時整段會唸出來。焦點預設落在「取消」而不是「確定」，Esc 也等同取消 —— 順手一個 Enter 不該把單子刪掉。
  • 長標題換行不裁切overflow-wrap: anywhere，永遠不用 ellipsis。單子的高度由內容決定。

05

領域模型與端點

契約已依這節寫成 api/openapi.yaml，之後以契約為準；這節維持成畫面對照表。01 節的原型已依 2026-09-08 的契約修訂重畫：category 下拉、description 欄位與 category-sequence 單號都已落地。

欄位型別不變條件在畫面上的位置
idstring(uuid)伺服器產生，唯讀，永不改變；給機器用，不是給人看的編號不顯示；只用於路由與請求
sequenceinteger伺服器產生，唯讀，≥ 1；每個 category 一個獨立計數器，唯一的是（category, sequence）這一對存根直排編號，與 category 合成 bug-0007；補零四位由前端做
titlestring必填，1–200 字，trim 後不得為空單子主體（唯讀）；由右上角選單的「編輯」修改
descriptionstring?選填，上限 2000 字新增／編輯彈窗的 <textarea>，有橫線的一塊區域；工單明細的說明區（唯讀）是看板上讀得到它的唯一位置；卡片正面不顯示（見下方註一、註五）
categoryenum必填，feat / bug；決定編號前綴，改它會從目標類別重新發號（見下方註三）新增／編輯彈窗的下拉選單；存根頂端的類別記號（實心 bug／空心 feat）與單號前綴都讀這個欄位
completedboolean必填，預設 false決定單子在哪一架；方框點一下切換（見下方註二）
dueDatedate?選填；早於今日且 completed = false → 逾期單子頁腳；逾期轉紅並掛文字標籤
createdAtdate-time伺服器產生，唯讀架內預設排序；工單明細頁腳印「開單」，卡片上不顯示
updatedAtdate-time伺服器產生，唯讀；每次 PUT 與 PATCH 都會動工單明細頁腳印「異動」，其餘畫面都不顯示
操作端點畫面觸發方式
GET/api/tasks?completed=兩個架各發一次帶參數的查詢，篩選在伺服器端
GET/api/tasks/{id}點卡片（整張都可點）開啟唯讀的工單明細。窗先用架上那一列畫滿，這支查詢只補 description；編輯彈窗開啟前也發一次，免得存檔時用空的說明蓋掉沒讀過的內容
POST/api/tasks看板右上「新增工單」（手機為右下浮動鈕）開啟彈窗，送出後進未完成架
PUT/api/tasks/{id}單子右上角選單 →「編輯」開啟同一張彈窗，帶入現值，送出即整筆更新
PATCH/api/tasks/{id}/completion點方框切換，或把單子拖到另一架；帶明確目標狀態（true／false）而非 toggle，反向操作不另開端點。樂觀更新，失敗回滾
DELETE/api/tasks/{id}同一個選單 →「刪除」跳確認彈窗，按下「確定」才送出；取消不打任何請求

註一 · description 已進 UI：新增／編輯共用的那張彈窗多一個 <textarea>，開單與改單自動一起有。它畫成有橫線的一塊區域而不是一條線 —— 版型本身就在說這格可以寫長一點，不必再寫一句「可多行輸入」。卡片正面仍然不放它：多一段說明文字會把看板變成閱讀介面，而看板要能一眼掃完。上限 2000 字只做驗證不做顯示，跟 title 同一條規則。看板現在有讀內文的入口了（2026-09-09 裁示，推翻前一版）：點卡片開一張唯讀的工單明細。前一版寫的是「不做」，理由是多一層展開會把看板推向閱讀介面 —— 那個顧慮由兩件事解掉：卡片正面仍然一個字都不放，看板照樣一眼掃完；而明細是另一張紙不是卡片上的展開，看板的版型一格都沒動。真正推翻它的是契約 —— GET /api/tasks/{id} 本來就在，卻只有編輯彈窗用得到：要讀一段說明得先按「編輯」，等於逼人打開一個會改資料的表單去做唯讀的事。

註二 · 狀態就是題目寫的那一個布林值，沒有多出 enum。看板的兩個架是 completed 的視覺投影，點方框等同 PATCH { "completed": … }，拖到另一架也是同一支端點。之後若真要有「進行中」，那是一次模型變更（boolean → enum）而不是前端多塞一個欄位，這版刻意不先做。

註三 · 工單編號不是 id，而是 category + sequence 算出來的顯示字串：`${category}-${String(sequence).padStart(4, "0")}`。契約走原始整數，補零到四位是前端的顯示責任。bug 與 feat 各有一個計數器，所以 bug-0001 與 feat-0001 會同時存在。也因為兩個計數器獨立，改類別時會從目標類別重新發號（feat-0003 → 例如 bug-0007），舊號作廢不回收；沿用舊號會跟既有的 bug-0003 撞號，而顯示編號撞號等於這個編號不能拿來指認單子。換號之所以無痛，是因為 id 是獨立的 uuid：網址與正在飛的請求都認 id，不受影響。代價是使用者手上記的號碼在搬類別後會變。分組、篩選、上色一律讀 category，不要去解析前綴。

註五 · 工單明細（第二聯）唯讀，底下只有「關閉」。全站兩張彈窗一律取消／確定，這一張不同是因為它沒有東西要「確定」—— 一張讀完就收起來的紙，唯一誠實的按鈕是關閉。編輯與刪除不放進來：那兩個動作在三點選單裡，一個 Esc 的距離，放進明細等於同一組動作有兩個入口，還會讓 modal 疊 modal（明細開編輯窗，關閉順序就開始難講）。狀態格也是唯讀，改狀態是卡片方框的事。開窗順序：先畫再補。卡片手上那一列（TaskSummary）已經有 description 以外的全部欄位，所以窗一開就畫滿，只有說明區等查詢 —— 不是整窗骨架，版面不會在資料到齊時跳一下。連點兩張卡時，先發的回應要用一個號碼比對擋掉，不能寫進後開的那張窗；關窗也一併作廢飛在路上的查詢。錯誤留在窗裡，不走看板那條載入失敗橫幅 —— 橫幅在 modal 後面，人看不到。

註四 · dueDate 是日期不是時間戳：單子是「某天」到期而不是「某個瞬間」到期，帶時區的時間戳會讓同一張單在不同時區看起來一個逾期一個沒有。契約裡也沒有 overdue 旗標 —— 逾期就是 dueDate < 今天 && !completed，前端自己算。伺服器算好的旗標在瀏覽器裡跨過午夜就過期了，而前端本來就要重算。
